# LinterCop Rules LC0051-LC0060

## LC0051: Possible Overflow Assigning (Warning)

**Rule**: Possible overflow assigning '{0}' to '{1}'. Do not assign a text to a target with smaller size.

**Why**: Assigning a longer text value to a shorter text field causes truncation, potentially losing data or creating invalid records.

**Instruction**: Always ensure source text length fits in target. Use CopyStr or add MaxLength to Labels.

**Correct Example**:
```al
field(10; "Short Code"; Code[10])
{
    Caption = 'Short Code';
}

procedure SetCode(LongValue: Text[50])
begin
    // Use CopyStr to safely truncate
    Rec."Short Code" := CopyStr(LongValue, 1, MaxStrLen(Rec."Short Code"));
end;

// For Labels, specify MaxLength
var
    ShortDescLbl: Label 'Description', MaxLength = 10;
```

**Incorrect Example**:
```al
field(10; "Short Code"; Code[10])
{
    Caption = 'Short Code';
}

procedure SetCode(LongValue: Text[50])
begin
    Rec."Short Code" := LongValue;  // VIOLATION: Possible overflow
end;
```

## LC0052: Internal Procedures Not Referenced (Info)

**Rule**: The {0} method {1} in {2} {3} is declared but never used.

**Why**: Unused internal procedures clutter the code and increase maintenance burden. They should be removed or the code should be reviewed.

**Instruction**: Remove unused internal procedures or mark them as intentionally reserved.

**Correct Example**:
```al
codeunit 50100 "VOL Sales Management"
{
    // Only procedures that are actually used
    internal procedure ProcessSales()
    begin
        ValidateOrder();
        PostOrder();
    end;

    local procedure ValidateOrder()  // Used by ProcessSales
    begin
        // Validation logic
    end;

    local procedure PostOrder()  // Used by ProcessSales
    begin
        // Posting logic
    end;
}
```

**Incorrect Example**:
```al
codeunit 50100 "VOL Sales Management"
{
    internal procedure ProcessSales()
    begin
        ValidateOrder();
    end;

    local procedure ValidateOrder()
    begin
        // Validation logic
    end;

    internal procedure UnusedProcedure()  // VIOLATION: Never called
    begin
        // Dead code
    end;
}
```

## LC0053: Internal Procedure Only Used In Current Object (Info)

**Rule**: The {0} method {1} is only used in the object {2} {3}.

**Why**: If an internal procedure is only used within its own object, it should be local instead. This provides better encapsulation.

**Instruction**: Change internal procedures that are only used locally to local procedures.

**Correct Example**:
```al
codeunit 50100 "VOL Sales Management"
{
    procedure ProcessOrder()
    begin
        ValidateFields();
        UpdateStatus();
    end;

    local procedure ValidateFields()  // CORRECT: local since only used here
    begin
        // Validation
    end;

    local procedure UpdateStatus()  // CORRECT: local since only used here
    begin
        // Status update
    end;
}
```

**Incorrect Example**:
```al
codeunit 50100 "VOL Sales Management"
{
    procedure ProcessOrder()
    begin
        ValidateFields();
        UpdateStatus();
    end;

    internal procedure ValidateFields()  // VIOLATION: Should be local
    begin
        // Only used in ProcessOrder above
    end;

    internal procedure UpdateStatus()  // VIOLATION: Should be local
    begin
        // Only used in ProcessOrder above
    end;
}
```

## LC0054: Follow Interface Object Name Guide (Info)

**Rule**: Interface name must start with the capital 'I' without any spaces.

**Why**: Following the 'I' prefix convention for interfaces makes them immediately identifiable and follows common programming conventions.

**Instruction**: ALL interface names must start with capital 'I' followed by PascalCase name without spaces.

**Correct Example**:
```al
interface IPaymentProcessor
{
    procedure ProcessPayment(Amount: Decimal): Boolean;
    procedure RefundPayment(TransactionId: Text): Boolean;
}

interface IDocumentHandler
{
    procedure ValidateDocument(var Document: Record "Sales Header"): Boolean;
    procedure PostDocument(var Document: Record "Sales Header"): Boolean;
}

interface INotificationService
{
    procedure SendNotification(Message: Text; Recipient: Text): Boolean;
}
```

**Incorrect Example**:
```al
interface PaymentProcessor  // VIOLATION: Missing 'I' prefix
{
    procedure ProcessPayment(Amount: Decimal): Boolean;
}

interface "I Payment Processor"  // VIOLATION: Contains spaces
{
    procedure ProcessPayment(Amount: Decimal): Boolean;
}

interface iPaymentProcessor  // VIOLATION: 'I' must be capital
{
    procedure ProcessPayment(Amount: Decimal): Boolean;
}
```

## LC0055: Tok Suffix For Token Labels (Info)

**Rule**: The suffix 'Tok' is meant to be used when the value matches name.

**Why**: The 'Tok' suffix indicates the label is a token (system value, not for translation). It should be used when the label value is the same as or closely matches the variable name.

**Instruction**: Use 'Tok' suffix for token labels where the value matches the name purpose.

**Correct Example**:
```al
var
    CustomerTok: Label 'Customer', Locked = true;  // Value matches name
    SalesHeaderTok: Label 'Sales Header', Locked = true;  // Value matches name
    PostingDateTok: Label 'Posting Date', Locked = true;  // Value matches name

    // Not a token - different purpose
    WelcomeMessageLbl: Label 'Welcome to the application!';  // Translation needed
```

**Incorrect Example**:
```al
var
    CustomerLabelTok: Label 'Welcome Message', Locked = true;
    // VIOLATION: Tok suffix but value doesn't match name - misleading
```

## LC0056: Empty Enum Value With Caption (Info)

**Rule**: Empty Enum values should not have a specified Caption property.

**Why**: Empty enum values (typically value 0 with empty string) represent an unset state. They shouldn't have a visible caption as this creates confusion.

**Instruction**: Don't specify Caption for empty enum values, or use an empty/space caption.

**Correct Example**:
```al
enum 50100 "VOL Status"
{
    Extensible = true;

    value(0; " ")  // Empty value - no Caption specified
    {
    }
    value(1; Active)
    {
        Caption = 'Active';
    }
    value(2; Inactive)
    {
        Caption = 'Inactive';
    }
}
```

**Incorrect Example**:
```al
enum 50100 "VOL Status"
{
    value(0; " ")
    {
        Caption = 'None';  // VIOLATION: Empty value shouldn't have visible caption
    }
    value(1; Active)
    {
        Caption = 'Active';
    }
}
```

## LC0057: Enum Value With Empty Caption (Info)

**Rule**: Enum values must have non-empty a Caption to be selectable.

**Why**: Non-empty enum values need captions so users can select them from dropdowns. Without captions, users see blank options.

**Instruction**: All meaningful enum values must have a Caption.

**Correct Example**:
```al
enum 50100 "VOL Payment Method"
{
    value(0; " ") { }  // Empty OK - represents unset

    value(1; Cash)
    {
        Caption = 'Cash';  // REQUIRED for non-empty values
    }
    value(2; CreditCard)
    {
        Caption = 'Credit Card';  // REQUIRED for non-empty values
    }
    value(3; BankTransfer)
    {
        Caption = 'Bank Transfer';  // REQUIRED for non-empty values
    }
}
```

**Incorrect Example**:
```al
enum 50100 "VOL Payment Method"
{
    value(1; Cash)
    {
        // VIOLATION: Missing Caption - users can't see this option
    }
    value(2; CreditCard)
    {
        Caption = '';  // VIOLATION: Empty caption
    }
}
```

## LC0058: Page Variable Method On Temporary Table (Warning)

**Rule**: {0}.{1}(): You cannot use a temporary record for the Record parameter.

**Why**: Some page methods (like Page.GetRecord) don't work with temporary records. This causes runtime errors.

**Instruction**: Don't use page record methods on temporary tables. Use alternative approaches.

**Correct Example**:
```al
procedure ShowCustomerCard()
var
    Customer: Record Customer;
    CustomerCard: Page "Customer Card";
begin
    if Customer.Get(CustomerNo) then begin
        CustomerCard.SetRecord(Customer);  // Real record - OK
        CustomerCard.Run();
    end;
end;
```

**Incorrect Example**:
```al
procedure ShowFromTemp()
var
    TempCustomer: Record Customer temporary;
    CustomerCard: Page "Customer Card";
begin
    // Fill TempCustomer...
    CustomerCard.SetRecord(TempCustomer);  // VIOLATION: Temporary record
    CustomerCard.Run();
end;
```

**Alternative for Temporary Records**:
```al
procedure ShowFromTemp()
var
    TempCustomer: Record Customer temporary;
    RealCustomer: Record Customer;
begin
    // Get real record from temp
    if RealCustomer.Get(TempCustomer."No.") then
        Page.Run(Page::"Customer Card", RealCustomer);
end;
```

## LC0059: Single Quote Escaping Issue Detected (Warning)

**Rule**: Single quote escaping issue detected: Use %1 or '''' for correct text.

**Why**: Single quotes in AL strings must be escaped by doubling them. Incorrect escaping causes compile or runtime errors.

**Instruction**: Use '''' (four single quotes) to represent one single quote in strings, or use %1 placeholders.

**Correct Example**:
```al
var
    MessageWithQuoteLbl: Label 'Customer''s order has been processed.';  // Escaped quote
    ApostropheTextLbl: Label 'It''s working correctly.';  // Escaped apostrophe

procedure ShowMessage()
begin
    Message('The customer''s name is %1', CustomerName);  // Escaped in Message
end;
```

**Incorrect Example**:
```al
var
    MessageWithQuoteLbl: Label 'Customer's order has been processed.';  // VIOLATION: Unescaped

procedure ShowMessage()
begin
    Message('The customer's name is %1', CustomerName);  // VIOLATION: Unescaped
end;
```

## LC0060: Property ApplicationArea On Api Page (Info)

**Rule**: The 'ApplicationArea' property is not applicable to API pages.

**Why**: API pages are accessed programmatically, not through the UI. ApplicationArea controls UI visibility and is irrelevant for APIs.

**Instruction**: Do NOT set ApplicationArea on API pages or their fields.

**Correct Example**:
```al
page 50100 "VOL Customer API"
{
    PageType = API;
    Caption = 'Customer API';
    APIPublisher = 'volpublisher';
    APIGroup = 'sales';
    APIVersion = 'v1.0';
    EntityName = 'customer';
    EntitySetName = 'customers';
    SourceTable = Customer;
    // NO ApplicationArea - not applicable for API

    layout
    {
        area(Content)
        {
            repeater(General)
            {
                field(number; Rec."No.")
                {
                    // NO ApplicationArea on fields either
                }
                field(displayName; Rec.Name)
                {
                }
            }
        }
    }
}
```

**Incorrect Example**:
```al
page 50100 "VOL Customer API"
{
    PageType = API;
    ApplicationArea = All;  // VIOLATION: Not applicable

    layout
    {
        area(Content)
        {
            repeater(General)
            {
                field(number; Rec."No.")
                {
                    ApplicationArea = All;  // VIOLATION: Not applicable
                }
            }
        }
    }
}
```
