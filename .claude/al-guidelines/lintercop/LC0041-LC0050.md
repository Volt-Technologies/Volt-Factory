# LinterCop Rules LC0041-LC0050

## LC0041: Empty Caption Locked (Info)

**Rule**: Empty captions should be locked.

**Why**: Empty captions are typically intentional (for fields that shouldn't display labels). Locking them indicates this is deliberate and prevents translation tools from flagging them as missing translations.

**Instruction**: When using empty Caption, also set Locked = true.

**Correct Example**:
```al
field(Spacer; '')
{
    Caption = '';
    Locked = true;  // Indicates intentionally empty
}

field("Line Discount %"; Rec."Line Discount %")
{
    Caption = '';
    Locked = true;  // Intentionally no label (shown elsewhere)
}
```

**Incorrect Example**:
```al
field(Spacer; '')
{
    Caption = '';  // VIOLATION: Empty caption should be locked
}
```

## LC0042: AutoCalcFields On Normal Fields (Warning)

**Rule**: The SetAutoCalcFields method should only be used with FlowFields or Blob fields.

**Why**: SetAutoCalcFields is specifically designed for FlowFields (which need calculation) and Blob fields (which need loading). Using it on normal fields has no effect and indicates a misunderstanding of the API.

**Instruction**: Only use SetAutoCalcFields for FlowFields and Blob fields.

**Correct Example**:
```al
procedure GetCustomerBalance(CustomerNo: Code[20]): Decimal
var
    Customer: Record Customer;
begin
    Customer.SetAutoCalcFields(Balance);  // Balance is a FlowField
    if Customer.Get(CustomerNo) then
        exit(Customer.Balance);
end;

procedure GetItemPicture(ItemNo: Code[20]): MediaSet
var
    Item: Record Item;
begin
    Item.SetAutoCalcFields(Picture);  // Picture is a Blob/MediaSet
    if Item.Get(ItemNo) then
        exit(Item.Picture);
end;
```

**Incorrect Example**:
```al
procedure GetCustomerName(CustomerNo: Code[20]): Text
var
    Customer: Record Customer;
begin
    Customer.SetAutoCalcFields(Name);  // VIOLATION: Name is not a FlowField
    if Customer.Get(CustomerNo) then
        exit(Customer.Name);
end;
```

## LC0043: SecretText (Info)

**Rule**: Use SecretText type to protect credentials and sensitive textual values.

**Why**: SecretText provides security for sensitive data by:
- Preventing values from appearing in debug output
- Masking values in telemetry
- Providing secure comparison methods

**Instruction**: Use SecretText for passwords, API keys, tokens, and other sensitive data.

**Correct Example**:
```al
procedure ConnectToAPI(ApiKey: SecretText)
var
    HttpClient: HttpClient;
    Headers: HttpHeaders;
begin
    HttpClient.DefaultRequestHeaders.Add('Authorization', ApiKey);
    // SecretText is automatically handled securely
end;

table 50100 "VOL API Setup"
{
    fields
    {
        field(1; "Primary Key"; Code[10]) { }
        field(10; "API Key"; SecretText)  // CORRECT: Use SecretText for secrets
        {
            Caption = 'API Key';
        }
    }
}
```

**Incorrect Example**:
```al
procedure ConnectToAPI(ApiKey: Text)  // VIOLATION: Should be SecretText
var
    HttpClient: HttpClient;
begin
    HttpClient.DefaultRequestHeaders.Add('Authorization', ApiKey);
    // API key visible in debug/telemetry!
end;

table 50100 "VOL API Setup"
{
    fields
    {
        field(10; "API Key"; Text[250])  // VIOLATION: Use SecretText
        {
            Caption = 'API Key';
        }
    }
}
```

## LC0044: Analyze Table Extension / Transfer Fields (Warning)

**Rule**: Conflicting ID, Name or Type with Table '{0}' / Records '{0}' and '{1}' have conflicting fields with the same ID.

**Why**: Table extensions and TransferFields operations require matching field structures. Conflicts in field IDs, names, or types cause runtime errors.

**Instruction**: When creating table extensions:
- Ensure field IDs don't conflict with base table
- Use unique IDs in the extension range (50000+)
- When using TransferFields, ensure field structures match

**Correct Example**:
```al
tableextension 50100 "VOL Customer Ext" extends Customer
{
    fields
    {
        field(50100; "VOL Custom Field"; Text[50])  // ID in extension range
        {
            Caption = 'Custom Field';
        }
    }
}
```

**TransferFields Example**:
```al
// Ensure Source and Target have matching field structures
procedure TransferData(Source: Record "Sales Header"; var Target: Record "Sales Header Archive")
begin
    // Fields must have same IDs and compatible types
    Target.TransferFields(Source);
end;
```

## LC0045: Zero Enum Value Reserved For Empty (Info)

**Rule**: Zero (0) Enum value should be reserved for Empty Value.

**Why**: By convention, enum value 0 represents an unset/empty state. Using 0 for a meaningful value can cause issues with default initialization.

**Instruction**: Reserve enum value 0 for empty/default state. Start meaningful values at 1.

**Correct Example**:
```al
enum 50100 "VOL Document Status"
{
    Extensible = true;

    value(0; " ")  // Empty/default
    {
        Caption = ' ';
    }
    value(1; Draft)
    {
        Caption = 'Draft';
    }
    value(2; Open)
    {
        Caption = 'Open';
    }
    value(3; Released)
    {
        Caption = 'Released';
    }
}
```

**Incorrect Example**:
```al
enum 50100 "VOL Document Status"
{
    Extensible = true;

    value(0; Draft)  // VIOLATION: 0 should be empty
    {
        Caption = 'Draft';
    }
    value(1; Open)
    {
        Caption = 'Open';
    }
}
```

## LC0046: Tok Labels Locked (Info)

**Rule**: Label with suffix Tok must be locked.

**Why**: Labels ending in "Tok" (Token) are meant for system use, not translation. They must be locked to prevent translation tools from modifying them.

**Instruction**: Labels with "Tok" suffix must have Locked = true.

**Correct Example**:
```al
var
    CustomerTableNameTok: Label 'Customer', Locked = true;
    ApiEndpointTok: Label '/api/v1/customers', Locked = true;
    DateFormatTok: Label 'yyyy-MM-dd', Locked = true;
```

**Incorrect Example**:
```al
var
    CustomerTableNameTok: Label 'Customer';  // VIOLATION: Missing Locked = true
    ApiEndpointTok: Label '/api/v1/customers';  // VIOLATION: Missing Locked = true
```

## LC0047: Locked Labels Tok (Hidden)

**Rule**: Locked Label must have a suffix Tok.

**Why**: Convention dictates that locked labels (which are not for translation) should have the "Tok" suffix for easy identification.

**Instruction**: Locked labels should have "Tok" suffix.

**Correct Example**:
```al
var
    MySystemValueTok: Label 'SYSTEM_VALUE', Locked = true;
    JsonPropertyNameTok: Label 'propertyName', Locked = true;
```

**Incorrect Example**:
```al
var
    MySystemValue: Label 'SYSTEM_VALUE', Locked = true;  // Should have Tok suffix
    JsonPropertyName: Label 'propertyName', Locked = true;  // Should have Tok suffix
```

## LC0048: Error With Text Constant (Info)

**Rule**: Use Error with a ErrorInfo or Label variable to improve telemetry.

**Why**: Using ErrorInfo or Label variables with Error() provides:
- Better telemetry and error tracking
- Translatable error messages
- Structured error information for troubleshooting

**Instruction**: Always use Label variables or ErrorInfo with Error().

**Correct Example**:
```al
var
    CustomerNotFoundErr: Label 'Customer %1 was not found.', Comment = '%1 = Customer No.';
    InvalidAmountErr: Label 'Amount %1 is invalid. Must be greater than zero.', Comment = '%1 = Amount';

procedure ValidateCustomer(CustomerNo: Code[20])
var
    Customer: Record Customer;
begin
    if not Customer.Get(CustomerNo) then
        Error(CustomerNotFoundErr, CustomerNo);
end;

procedure ValidateAmount(Amount: Decimal)
var
    ErrorInfo: ErrorInfo;
begin
    if Amount <= 0 then begin
        ErrorInfo.Message := StrSubstNo(InvalidAmountErr, Amount);
        ErrorInfo.DetailedMessage := 'Validation failed in ValidateAmount procedure';
        Error(ErrorInfo);
    end;
end;
```

**Incorrect Example**:
```al
procedure ValidateCustomer(CustomerNo: Code[20])
var
    Customer: Record Customer;
begin
    if not Customer.Get(CustomerNo) then
        Error('Customer %1 was not found.', CustomerNo);  // VIOLATION: Use Label
end;
```

## LC0049: Page Without SourceTable (Info)

**Rule**: SourceTable property not defined on {0} '{1}'.

**Why**: Most pages need a SourceTable to display data. Pages without SourceTable are rare (worksheets, dialogs) and should be intentional.

**Instruction**: Set SourceTable on all pages except special worksheet or dialog pages.

**Correct Example**:
```al
page 50100 "VOL Customer List"
{
    Caption = 'Customer List';
    PageType = List;
    SourceTable = "VOL Customer";  // REQUIRED

    layout
    {
        area(Content)
        {
            repeater(General)
            {
                field("No."; Rec."No.") { }
                field(Name; Rec.Name) { }
            }
        }
    }
}
```

**Exception - Worksheet Pages**:
```al
page 50101 "VOL Configuration Wizard"
{
    Caption = 'Configuration Wizard';
    PageType = NavigatePage;
    // No SourceTable - this is a wizard dialog
}
```

## LC0050: Operator And Placeholder In Filter Expression (Info)

**Rule**: Found operator '{0}' together with placeholder '{1}' in filter expression.

**Why**: Mixing filter operators with placeholders in SetFilter can produce unexpected results. The placeholder might be interpreted as part of the filter operator.

**Instruction**: Be careful when combining operators and placeholders. Use clear separation.

**Correct Example**:
```al
procedure FilterByPattern(Pattern: Text)
var
    Item: Record Item;
begin
    // Clear approach - build filter separately
    Item.SetFilter(Description, '@*' + Pattern + '*');
end;

procedure FilterByRange(StartDate: Date; EndDate: Date)
var
    SalesHeader: Record "Sales Header";
begin
    // Use SetRange for simple ranges
    SalesHeader.SetRange("Posting Date", StartDate, EndDate);
end;
```

**Potential Issue**:
```al
procedure FilterItems(FilterValue: Text)
var
    Item: Record Item;
begin
    // Be careful: if FilterValue contains special chars like | or ..
    Item.SetFilter(Description, FilterValue);  // Could cause issues

    // Better: validate or escape FilterValue first
    if StrPos(FilterValue, '|') > 0 then
        Error(InvalidFilterErr);
    Item.SetFilter(Description, '@' + FilterValue);
end;
```
