# LinterCop Rules LC0071-LC0080

## LC0071: Do Not Set IsHandled To False (Info)

**Rule**: Do not set the 'IsHandled' parameter to 'false' or any value that evaluates to false.

**Why**: Setting IsHandled to false in a subscriber undoes handling from previous subscribers. This breaks the event pattern where multiple subscribers can participate.

**Instruction**: Only set IsHandled to true when handling. Never set it to false.

**Correct Example**:
```al
[EventSubscriber(ObjectType::Codeunit, Codeunit::"Sales-Post", OnBeforePostSalesDoc, '', false, false)]
local procedure HandleOnBeforePostSalesDoc(var SalesHeader: Record "Sales Header"; var IsHandled: Boolean)
begin
    // Check if already handled by another subscriber
    if IsHandled then
        exit;

    // If we handle it, set to true
    if SalesHeader."Special Processing" then begin
        SpecialPostingLogic(SalesHeader);
        IsHandled := true;
    end;
    // If we don't handle it, just exit without touching IsHandled
end;
```

**Incorrect Example**:
```al
[EventSubscriber(ObjectType::Codeunit, Codeunit::"Sales-Post", OnBeforePostSalesDoc, '', false, false)]
local procedure HandleOnBeforePostSalesDoc(var SalesHeader: Record "Sales Header"; var IsHandled: Boolean)
begin
    if SalesHeader."Special Processing" then begin
        SpecialPostingLogic(SalesHeader);
        IsHandled := true;
    end else
        IsHandled := false;  // VIOLATION: Don't set to false
end;
```

## LC0072: Check Procedure Documentation Comment (Info)

**Rule**: The documentation comment does not match the procedure syntax.

**Why**: XML documentation comments should accurately describe the procedure's parameters and return value. Mismatched documentation is misleading.

**Instruction**: Ensure XML documentation matches the actual procedure signature.

**Correct Example**:
```al
/// <summary>
/// Calculates the total amount for a sales document.
/// </summary>
/// <param name="SalesHeader">The sales header record to calculate.</param>
/// <returns>The calculated total amount including VAT.</returns>
procedure CalculateTotalAmount(SalesHeader: Record "Sales Header"): Decimal
begin
    // Implementation
end;

/// <summary>
/// Validates the customer credit limit.
/// </summary>
/// <param name="CustomerNo">The customer number to validate.</param>
/// <param name="Amount">The order amount to check against credit limit.</param>
/// <returns>True if within credit limit, false otherwise.</returns>
procedure ValidateCreditLimit(CustomerNo: Code[20]; Amount: Decimal): Boolean
begin
    // Implementation
end;
```

**Incorrect Example**:
```al
/// <summary>
/// Calculates the total amount.
/// </summary>
/// <param name="SalesLine">The sales line.</param>  // VIOLATION: Parameter doesn't exist
/// <returns>The amount.</returns>
procedure CalculateTotalAmount(SalesHeader: Record "Sales Header"): Decimal
begin
    // Documentation mentions SalesLine but parameter is SalesHeader
end;
```

## LC0073: Event Publisher IsHandled By Var (Warning)

**Rule**: The Handled parameter in the event signature should be passed by var.

**Why**: If IsHandled/Handled parameters aren't passed by var, subscribers can't communicate back that they've handled the event.

**Instruction**: ALWAYS use 'var' for IsHandled/Handled parameters in event publishers.

**Correct Example**:
```al
[IntegrationEvent(false, false)]
procedure OnBeforePostDocument(var SalesHeader: Record "Sales Header"; var IsHandled: Boolean)
begin
    // IsHandled passed by var - subscribers can set it
end;

[IntegrationEvent(false, false)]
procedure OnValidateQuantity(var SalesLine: Record "Sales Line"; var Handled: Boolean)
begin
    // Handled passed by var
end;
```

**Incorrect Example**:
```al
[IntegrationEvent(false, false)]
procedure OnBeforePostDocument(var SalesHeader: Record "Sales Header"; IsHandled: Boolean)
begin
    // VIOLATION: IsHandled should be 'var IsHandled: Boolean'
    // Subscribers can't indicate they handled it
end;
```

## LC0074: FlowFilter Assignment (Warning)

**Rule**: Direct assignment to the {0} field of type FlowFilter invalidates the filter logic.

**Why**: FlowFilter fields are meant to be set using filtering methods (SetRange, SetFilter). Direct assignment doesn't work correctly and invalidates the FlowField calculations.

**Instruction**: Use SetRange or SetFilter to set FlowFilter values.

**Correct Example**:
```al
procedure CalculateCustomerBalance(CustomerNo: Code[20]; StartDate: Date; EndDate: Date): Decimal
var
    Customer: Record Customer;
begin
    Customer.Get(CustomerNo);
    // Set FlowFilter using filtering methods
    Customer.SetRange("Date Filter", StartDate, EndDate);
    Customer.SetRange("Global Dimension 1 Filter", 'SALES');
    Customer.CalcFields(Balance);
    exit(Customer.Balance);
end;
```

**Incorrect Example**:
```al
procedure CalculateCustomerBalance(CustomerNo: Code[20]; StartDate: Date): Decimal
var
    Customer: Record Customer;
begin
    Customer.Get(CustomerNo);
    // VIOLATION: Direct assignment to FlowFilter
    Customer."Date Filter" := StartDate;
    Customer.CalcFields(Balance);
    exit(Customer.Balance);
end;
```

## LC0075: Record Get Procedure Arguments (Warning)

**Rule**: Invalid arguments in .Get() method for record {0}: {1}. Incorrect number or type of arguments.

**Why**: The Get() method requires arguments matching the table's primary key fields in exact number, order, and compatible types.

**Instruction**: Match Get() arguments to the table's primary key definition.

**Correct Example**:
```al
// Sales Header has composite primary key: Document Type + No.
procedure GetSalesOrder(OrderNo: Code[20])
var
    SalesHeader: Record "Sales Header";
begin
    // Correct: Both key fields provided in order
    if SalesHeader.Get(SalesHeader."Document Type"::Order, OrderNo) then
        ProcessOrder(SalesHeader);
end;

// Customer has single primary key: No.
procedure GetCustomer(CustomerNo: Code[20])
var
    Customer: Record Customer;
begin
    // Correct: Single key field
    if Customer.Get(CustomerNo) then
        ProcessCustomer(Customer);
end;
```

**Incorrect Example**:
```al
procedure GetSalesOrder(OrderNo: Code[20])
var
    SalesHeader: Record "Sales Header";
begin
    // VIOLATION: Missing Document Type argument
    if SalesHeader.Get(OrderNo) then
        ProcessOrder(SalesHeader);

    // VIOLATION: Wrong order of arguments
    if SalesHeader.Get(OrderNo, SalesHeader."Document Type"::Order) then
        ProcessOrder(SalesHeader);
end;
```

## LC0076: Table Relation Too Long (Warning)

**Rule**: The related field has length {0} ({1}) which is longer than the target field length {2} ({3}).

**Why**: If a TableRelation points to a field that's longer than the source field, data can be truncated when copied, causing referential integrity issues.

**Instruction**: Ensure source field length is >= related field length.

**Correct Example**:
```al
table 50100 "VOL Document"
{
    fields
    {
        field(10; "Customer No."; Code[20])  // Same length as Customer."No."
        {
            Caption = 'Customer No.';
            TableRelation = Customer."No.";  // Customer.No. is Code[20]
        }
        field(20; "Vendor No."; Code[20])  // Same length as Vendor."No."
        {
            Caption = 'Vendor No.';
            TableRelation = Vendor;  // Vendor.No. is Code[20]
        }
    }
}
```

**Incorrect Example**:
```al
table 50100 "VOL Document"
{
    fields
    {
        field(10; "Customer No."; Code[10])  // VIOLATION: Shorter than Customer."No."
        {
            Caption = 'Customer No.';
            TableRelation = Customer."No.";  // Customer.No. is Code[20] - too long!
        }
    }
}
```

## LC0077: Use Parenthesis For Function Call (Info)

**Rule**: You must specify open and close parenthesis after '{0}'.

**Why**: Function calls should always include parentheses, even when no parameters are passed. This improves code clarity and consistency.

**Instruction**: ALWAYS use () when calling functions, even without parameters.

**Correct Example**:
```al
procedure ProcessData()
var
    Customer: Record Customer;
begin
    Customer.FindFirst();  // Correct: parentheses included
    Customer.CalcFields();  // Correct: parentheses included
    Customer.Reset();  // Correct: parentheses included

    if Customer.IsEmpty() then  // Correct: parentheses included
        exit;

    ProcessCustomer(Customer);  // Correct: has parameters
end;
```

**Incorrect Example**:
```al
procedure ProcessData()
var
    Customer: Record Customer;
begin
    Customer.FindFirst;  // VIOLATION: Missing ()
    Customer.Reset;  // VIOLATION: Missing ()

    if Customer.IsEmpty then  // VIOLATION: Missing ()
        exit;
end;
```

## LC0078: Temporary Records Should Not Trigger Table Triggers (Info)

**Rule**: Temporary records should not trigger the table triggers.

**Why**: Table triggers (OnInsert, OnModify, OnDelete) typically contain business logic meant for permanent records. Running them on temporary records can cause:
- Unintended side effects
- Performance issues
- Logic errors

**Instruction**: Use RunTrigger = false when working with temporary records.

**Correct Example**:
```al
procedure ProcessTempData()
var
    TempItem: Record Item temporary;
begin
    TempItem.Init();
    TempItem."No." := 'TEMP001';
    TempItem.Insert(false);  // Don't run triggers for temp records

    TempItem.Description := 'Updated';
    TempItem.Modify(false);  // Don't run triggers

    TempItem.Delete(false);  // Don't run triggers
end;

procedure BulkCopyToTemp(var Source: Record Item; var TempTarget: Record Item temporary)
begin
    if Source.FindSet() then
        repeat
            TempTarget := Source;
            TempTarget.Insert(false);  // No triggers for temp
        until Source.Next() = 0;
end;
```

**Incorrect Example**:
```al
procedure ProcessTempData()
var
    TempItem: Record Item temporary;
begin
    TempItem.Init();
    TempItem."No." := 'TEMP001';
    TempItem.Insert(true);  // VIOLATION: Triggers on temporary record
    // or
    TempItem.Insert();  // VIOLATION: Default is true, triggers will run
end;
```

## LC0079: Non Public Event Publisher (Info)

**Rule**: Event Publishers should be local or internal.

**Why**: Event publishers that are public become part of your extension's API surface. If they don't need to be called directly by other extensions, they should be restricted.

**Instruction**: Make event publishers local or internal unless they need to be publicly callable.

**Correct Example**:
```al
codeunit 50100 "VOL Sales Events"
{
    // Local event - only this codeunit can raise it
    [IntegrationEvent(false, false)]
    local procedure OnBeforeProcessOrder(var SalesHeader: Record "Sales Header")
    begin
    end;

    // Internal event - only this extension can raise it
    [IntegrationEvent(false, false)]
    internal procedure OnAfterProcessOrder(var SalesHeader: Record "Sales Header")
    begin
    end;

    procedure ProcessOrder(var SalesHeader: Record "Sales Header")
    begin
        OnBeforeProcessOrder(SalesHeader);
        // Processing logic
        OnAfterProcessOrder(SalesHeader);
    end;
}
```

**Incorrect Example**:
```al
codeunit 50100 "VOL Sales Events"
{
    // VIOLATION: Public event publisher (unless intentionally public API)
    [IntegrationEvent(false, false)]
    procedure OnBeforeProcessOrder(var SalesHeader: Record "Sales Header")
    begin
    end;
}
```

## LC0080: Analyze Json Token JPath (Warning)

**Rule**: Double quote character detected in JPath expression. Replace double quotes in JPath expressions with two single quotes.

**Why**: JPath expressions in AL use single quotes for string values. Double quotes cause parsing errors.

**Instruction**: Use two single quotes ('') instead of double quotes (") in JPath expressions.

**Correct Example**:
```al
procedure GetJsonValue(): Text
var
    JToken: JsonToken;
    JObject: JsonObject;
begin
    JObject.ReadFrom('{"name": "John", "status": "active"}');

    // Correct: Using single quotes in JPath
    if JObject.SelectToken('$.name', JToken) then
        exit(JToken.AsValue().AsText());

    // Correct: String values in JPath use single quotes
    if JObject.SelectToken('$[?(@.status==''active'')]', JToken) then
        exit('Found active');
end;
```

**Incorrect Example**:
```al
procedure GetJsonValue(): Text
var
    JToken: JsonToken;
    JObject: JsonObject;
begin
    JObject.ReadFrom('{"name": "John", "status": "active"}');

    // VIOLATION: Using double quotes in JPath filter
    if JObject.SelectToken('$[?(@.status=="active")]', JToken) then
        exit('Found');
end;
```
